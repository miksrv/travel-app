# Phase 8 — Заморозка мультиязычности

## Решение

Английская версия (`/en`) **замораживается**, не удаляется. Новые фичи разрабатываются только на русском. Время, которое тратилось на переводы — перераспределяется на SEO и контент.

## Почему

- Трафик с `/en/*` страниц минимален: контент (описания мест, комментарии) — на русском, целевая аудитория — русскоязычная
- Каждая новая фича требует переводов → тормозит разработку
- Всё семантическое ядро проекта — русскоязычное, EN не вносит вклада в цель 1000/сутки
- Половинчатый EN (русский контент + английский интерфейс) не даёт ценности ни русским, ни иностранным пользователям

## Почему не удалять полностью

Удаление `/en/*` страниц даст 404 на проиндексированных URL и сломает входящие ссылки. Заморозка с noindex безопаснее.

## Что делаем

- [ ] Убрать `/en/*` из `sitemap.tsx` — Google перестанет активно обходить эти страницы
- [ ] Добавить `noindex` на все `/en/*` страницы — через `next.config.js` или `_middleware.ts`
- [ ] Убрать `hreflang` теги со всех страниц — некорректный hreflang хуже чем его отсутствие
- [ ] Убрать language switcher из UI — не показывать пользователям несуществующую опцию
- [ ] Оставить `next-i18next` инфраструктуру нетронутой — не мешает, понадобится если вернёмся

## Что НЕ делаем

- Не удаляем `/en/*` маршруты — пусть отдают страницы, но без индексации
- Не удаляем переводы из `public/locales/en/` — оставляем как есть
- Не переписываем компоненты под one-locale — лишняя работа без выгоды

## Когда вернуться к теме

Если трафик вырастет до 1000+/сутки и появится реальная доля EN-пользователей (>10%) — пересмотреть решение. До тех пор EN — заморожен.
